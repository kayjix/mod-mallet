# 0089 When the game rewrites the load order, it is told why

- Status: accepted
- Date: 2026-11-25

## Context

Skyrim Special Edition and the games like it keep the list of active
plugins in `Plugins.txt`. Vortex writes it, with the header "Automatically
generated by Vortex", and keeps every plugin in its order in
`loadorder.txt` next to it. When the game starts and finds a plugin it
cannot load, it switches that plugin off and writes `Plugins.txt` again
with a header of its own ("This file is used by Skyrim to keep track of
your downloaded content."), the plugins it switched off at the top. At its
next start Vortex finds a list it did not write and warns that another
program changed the load order. Users with Mod Mallet installed suspect Mod
Mallet.

On the user's setup the game did this and switched off three plugins:
`Lux Orbis - JK Sky Haven Forge patch.esp`, `Lux Via - NSUTR.esp` and
`Stendarr Rising - NSUTR Patch.esp`. Read from the files:

- `Lux Orbis - JK Sky Haven Forge patch.esp` needs `JK's SkyHaven
  Forge.esp`; the two others need `Prometheus_No_snow_Under_the_roof.esp`
  (No Snow Under The Roof, "NSUTR").
- Neither master is in the Data folder. Their mods, "JK's Skyhaven forge"
  and "No Snow Under The Roof", are installed in Vortex but switched off;
  the mods with the three patches (Lux Orbis, Lux Via's patch hub,
  Stendarr Rising) are on.
- `loadorder.txt` still lists the three at their places (172, 261, 263);
  in the game's `Plugins.txt` they are the first lines, unticked.

Missing masters are already a finding (`plugins.master-missing`), but only
for plugins the game loads: once the game switched them off, nothing was
said, and the plugins' changes were silently missing.

## Decision

1. **Who wrote the list is read from its header.** The game's header
   ("This file is used by … to keep track of …") and Vortex's ("generated
   by Vortex") are told apart; anything else, such as Mod Organizer's
   profile list, is left alone. Only the games whose list marks active
   plugins with `*` are read this way.
2. **What the game switched off.** Where the game wrote the list, a plugin
   counts as switched off by the game if it is listed unticked and either
   stands in the block of unticked plugins at the top, where the game puts
   them, or could not be loaded at all (a missing master, no file, a file
   that is not a plugin). Where Vortex's `loadorder.txt` is there, only
   plugins it lists count, in its order. Plugins of the game itself are
   never counted.
3. **Why, from the files.** For each plugin, in this order: its file is
   not in the Data folder; its file does not read as a plugin; masters it
   names are not among the plugins the game loads (each with whether its
   file is there and the switched-off mod that has it, from the mod
   manager's state, ADR 0061); otherwise, if more plugins are on than the
   game loads (254 full, 4096 light), too many; else not known.
4. **One finding, `plugins.game-rewrote-load-order`**, for the setup: the
   game, the plugins, the cause they share (or "mixed"), the missing
   masters and the switched-off mods that have them. Its summary says what
   to do and, with Vortex, that Vortex's warning about another program was
   the game, not Mod Mallet. It carries the ways out as actions, on the
   user's click only (ADR 0020): `EnableMod` for each switched-off mod with
   a missing master, and `DisablePlugins` for the plugins (ADR 0073), so
   that Vortex's list agrees with the game's.
5. **Only reads.** Nothing writes `Plugins.txt` or `loadorder.txt`; the
   list is settled by the mod manager.

## Consequences

- On the user's setup: "Skyrim Special Edition switched off 3 plugins at
  its last start", because they need `JK's SkyHaven Forge.esp` and
  `Prometheus_No_snow_Under_the_roof.esp`, which "JK's Skyhaven forge V1"
  and "No Snow Under The Roof 3.2" have but which are switched off; two
  buttons switch those mods on or the three patches off in Vortex.
- Vortex's state backup does not keep Skyrim's plugin list (its
  `loadOrder` part holds other games only), and the link's state snapshot
  has no plugin list either; what Vortex meant to have on is inferred from
  `loadorder.txt` and from which mods are on.
- A plugin the user switched off on purpose, lying further down the list
  and loadable, is not reported. One with a missing master is, wherever it
  stands: the game would switch it off anyway.
- The text of the lists is read as UTF-8, or else Windows-1252.

## Alternatives considered

- **Compare with the plugins Vortex keeps on.** Vortex does not write that
  anywhere Mod Mallet can read once the game has replaced the file.
- **Report it through `plugins.master-missing`.** That finding is about a
  plugin the game tries to load and crashes on; these the game skipped,
  and the user's question is a different one: why Vortex says the load
  order was changed.
- **Write Vortex's list back.** Mod Mallet does not write into the mod
  manager's data (CLAUDE.md); the mod manager does it on the user's click.
