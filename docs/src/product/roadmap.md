# Roadmap

Each milestone is useful on its own and is measured against a problem that
was found by hand in a real setup. A milestone is done when Mod Mallet finds
that problem without help and the reference cases are covered by synthetic
tests.

Milestones 1 to 4 need no user interface beyond the command line. The
desktop app grows only once the findings are right.

| # | Milestone | Reference problem it must find |
|---|---|---|
| 0 | **Foundation** (done). Workspace, lints, CI, documentation, and one check running end to end. | A script extender plugin that the game switched off because it does not support the game version. |
| 1 | **Who wins** (done for files and characters). Read the load order, loose files, archives and character records; determine which file and which version of a character the game uses. Records of an NPC overhaul overridden by a later plugin. |
| 2 | **Installer re-check** (done). Read each mod's installer from its archive and compare the options that were chosen with what the installer would tick now. Since then as well: plugins generated by DynDOLOD, Synthesis, Wrye Bash or Mator Smash whose masters no longer load in the order the tool saw. Further setup checks (shader framework present, generated files other than plugins out of date) are still open. | A compatibility patch that was not installed because its target mod was installed afterwards. |
| 3 | **References** (done for loose meshes that replace a mesh from an archive). Read which textures a mesh uses and compare a replacement mesh with the one it replaces. Since then as well: loose meshes in the format of another game or edition, such as meshes of the original Skyrim left in a mod for the Special Edition. Since then as well: textures that loose meshes use for their colour or surface and that nothing in the game provides. Still open: both for meshes inside archives. | Meshes of one mod pointing at their own textures, so a texture overhaul leaves visible mismatched patches. |

Done since as well: the places of the game's map on it, by kind and by whether the game or a mod put them there, collisions pinned to their point and named by the nearest place, and a 3D relief of the land ([ADR 0031](../adr/0031-places-on-the-map-and-a-3d-relief.md)). ## Adapters planned along the way

- **Mod Organizer 2** as the second mod manager, to prove that the
  [`ModSource`](../adr/0009-mod-managers.md) seam holds.
- **The other Bethesda games** (begun: Skyrim VR, Skyrim, Fallout 4, Fallout 4 VR, New Vegas, Fallout 3 and Oblivion are found and read with the checks that need only the shared formats; see [ADR 0036](../adr/0036-one-adapter-for-the-bethesda-family.md)). Done since: their place names in English and the kinds of their places; Fallout 4's meshes in the 3D view and in the texture checks. Done since as well: Fallout 4's material files (`.bgsm`, `.bgem`), from which the 3D view takes the textures. Done since as well: Oblivion's meshes, which do not say where their blocks lie and are read block by block. Done since as well: Oblivion's animated meshes (doors, gates) and their Havok collision data; blocks of types the reader does not know, such as particle systems, are measured by where the next known block starts, so that 8,891 of the game's 9,612 meshes are now read to their last byte. Still open: Oblivion's creatures and clothes in their skinned pose; faces in Fallout 4; Oblivion Remastered.
- **Generators** such as DynDOLOD, Nemesis or Seamless Studio: their output
  is derived from the load order and goes stale when the load order changes.
  Mod Mallet should notice that and say so (begun: the plugins they
  generate, by the order of their masters; still open: generated files
  that are not plugins, such as LOD meshes and behaviour files).
